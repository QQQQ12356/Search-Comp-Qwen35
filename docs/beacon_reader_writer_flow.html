1. 为什么需要 Reader / Writer

Qwen3.5-2B 是混合 decoder：24 层里 6 层 full_attention（标准 QKV 缓存，长度随上下文增长），其余 18 层 linear_attention（GatedDeltaNet，固定尺寸循环状态）。

full_attention 历史 → K/V sequence cache → 长度随上下文增长 → 需压缩成 Beacon K/V。

linear_attention 历史 → recurrent matrix state + short conv state → 尺寸固定，但内容仍含全部历史。

固定尺寸不代表“不含原始文档信息”。若压缩窗口结束后直接保留原生状态，后续 token 仍能读到原始文档 → 形成旁路：

图1　删除 full-attention K/V 不足以防泄漏：linear 原生状态若保留，原始文档仍能绕过 Beacon 影响后续生成。

2. 总体运行流程

入口是 BeaconQwen3_5ForCausalLM.forward → 驱动 _Qwen3BeaconMemory 状态机。

图2　在线搜索循环：<search> → 检索 → <information> → Beacon 压缩 → 续生成，直到 <answer>。

主循环 _beacon_forward()（beacon_qwen3.py:708）伪代码：

prepare()        # 全序列 + regions → 切成 keep / compress 交替 segment
while not memory.finish:
    step()             # 切一个窗口（含追加的 beacon token）
    _native_forward()  # 逐层前向
        full_attention 层 → BeaconQwen3Attention（Beacon 自注意力）
        linear_attention 层 → Reader + Writer
    update_memory()    # full-attn 层选择提交 beacon K/V 或全量 K/V
output()               # 汇总跨窗口累积的 loss

3. 窗口状态机：keep / compress

prepare()（beacon_qwen3.py:302）把序列在 token 空间切成片段。给定文档区间 regions=[(s₁,e₁),(s₂,e₂),…]：

[(0, s₁,      keep),
 (s₁, e₁,    compress),
 (e₁, s₂,    keep),
 (s₂, e₂,    compress),
 …
 (last_end, L, keep)]

step()（beacon_qwen3.py:323）按 beacon_window 切当前窗口并定策略：

段模式Beacon 数store说明
keep0cache整窗口 K/V 全部保留（问题/think/search/answer）
compress·满窗口window/ratiobeacon末尾追加 beacon，只压缩文档正文
compress·尾部max(1, ceil(rem/ratio))beacon不足一片也压缩，保证任意长度文档都被覆盖

窗口 token 从 [d₁..d_D] 扩展为 [d₁..d_D, b₁..b_B]；Beacon 用虚拟 id vocab_size，由独立 beacon_embed_tokens 嵌入（初始化自 EOS，可训练）。_step_beacon_indices 同步标记：

[0, 0, …, 0, 1, 1, …, 1]   # 0 = 普通 token，1 = beacon

beacon_pos="intersect" 时（beacon_qwen3.py:365），改为每个 chunk 内每 ratio 个 token 后插入一个 beacon（见 beacon_intersect_order），掩码在 chunk 内保留完整因果可见性。

4. Full-attention：Beacon 自注意力（BeaconQwen3Attention）

分区投影：普通 token 用预训练 q/k/v/o_proj；Beacon 位置用独立可训练 beacon_{q,k,v,o}_proj，经 torch.where(bi==0, original, beacon) token 级切换（_qkv，beacon_qwen3.py:135）。beacon_param 决定哪些投影独立，默认 q k v。注意 Qwen3.5 的 q_proj 同时输出 query 与 gate，gate 随 query 一并切换。

RoPE 前缓存：持久 cache 存 RoPE 之前的 K/V，每窗口把 past+current 整体重施加 mRoPE（beacon_qwen3.py:226），query 只用末尾 cur_len 位置。

提交（update_memory，beacon_qwen3.py:407）：compress 窗口只 slice 出 Beacon K/V 入持久 cache；keep 窗口全量追加。原始文档 K/V 只存在于当前窗口内部，窗口结束即丢弃。

图3　full-attention 层窗口前向与提交（update_memory）。

5. Linear-attention 层：Reader（读文档）

_linear_attention_forward()（beacon_qwen3.py:661）是显式、可微分的 GatedDeltaNet 前向，彻底摆脱 HuggingFace DynamicCache 的隐式跨窗口状态：

P = in_proj_qkv(H)
P_context = concat(C_prev, P)                 # causal conv 左上下文
Mixed = SiLU(DepthwiseCausalConv(P_context))
[Q, K, V] = split(Mixed)
beta = sigmoid(in_proj_b(H))
g    = -exp(A_log) * softplus(in_proj_a(H) + dt_bias)
[O, S_reader] = GatedDeltaRule(Q, K, V, g, beta, initial_state=S_prev)
O    = out_proj(gated_rmsnorm(O, in_proj_z))

产出 reader_recurrent（next_recurrent）与 reader_conv（next_conv）两个临时状态。

关键在“临时”。（_native_forward，beacon_qwen3.py:587-599）： 
keep 段:      initial = previous_recurrent            # 直接继续累积
compress 段:  initial = previous_recurrent.clone()    # 拷贝当初始态，读完丢弃
clone() 保证文档窗口对原生状态 previous_recurrent 不产生 in-place 污染。Reader 读完文档、Beacon 能读到文档信息，但原生状态不提交。

6. Linear-attention 层：Writer（写回持久状态）

6.1 触发与输入

compress 窗口完成该层 attention residual + MLP 后，取该层 Beacon 位置输出隐状态（beacon_qwen3.py:605-614）：

B_l = hidden[:, _step_beacon_indices.bool()]            # beacon 位置隐状态
_linear_recurrent[idx] = writer(B_l, previous_recurrent) # 写回持久状态
_linear_conv.pop(idx, None)                              # 清空卷积尾状态

B_l 已融合当前文档窗口、历史 keep/Beacon memory、该层 reader 输出与 MLP —— writer 不直接读原始 token state，只读 decoder 形成的 Beacon 激活。

6.2 低秩参数化（BeaconLinearStateWriter，beacon_qwen3.py:40）

Z = Up(SiLU(Down(LayerNorm(B_l))))      # hidden → rank → heads*(k+v+decay+beta)
[key, value, decay, beta] = split(Z)

Down: hidden→rank（beacon_linear_writer_rank，默认 128）是低秩瓶颈，writer 因此可训练且量可控。初始 up.bias 置零、decay bias 段填 4.0（sigmoid(4.0)≈0.982），让 writer 一开始尽量保持状态稳定。

6.3 状态更新（FP32，顺序叠加每个 beacon）

图4　Writer 状态更新（FP32，逐 beacon 顺序叠加）。

初始 S 是压缩窗口进入前的持久状态（不是吸收过文档的 S_reader）；不存在则全零。整个叠加以 FP32 维护，降低长序列累积的数值风险。

6.4 卷积状态处理

compress 窗口结束即 delete _linear_conv[idx]：卷积尾状态直接含最近若干 projected token，若保留会明确残留原始文档或 Beacon 邻 token。下一段从零卷积左上下文开始，仍可通过 writer recurrent state 与 full-attention Beacon K/V 使用压缩记忆 —— 为严格边界接受的局部连续性折中。

keep 窗口相反：reader recurrent + conv 状态都直接提交（beacon_qwen3.py:612-614）。

图5　Reader 与 Writer 分工：Reader 读即弃，Writer 由 Beacon 激活写回持久态。

7. 一个压缩窗口的完整逐层过程

设窗口含 D 个文档 token、B 个 Beacon，一次 _native_forward()：

第 l 层内部 Decision 
1. Embedding
   document ids → original embedding
   beacon virtual ids → beacon_embed_tokens（自 EOS 初始化，可训练）

2. For layer l = 1 .. N
   a. input layer norm

   b1. if full_attention:
       普通/Beacon 分区投影 → cat 持久 K/V → 整体 mRoPE + causal attention
       保留当前窗口增量 K/V（RoPE 前）暂缓提交

   b2. if linear_attention:
       initial = previous_recurrent            # keep：直接续
       initial = previous_recurrent.clone()    # compress：reader 临时拷贝
       显式 causal conv + GatedDeltaNet reader → 临时 reader_recurrent/conv

   c. attention residual
   d. post-attention norm + MLP residual

   e. if linear_attention 且当前窗口是 compress:
       beacon_hidden = hidden[beacon_mask]
       writer(beacon_hidden, pre-window state) → commit 持久状态
       丢弃临时 conv 状态

   f. if linear_attention 且当前窗口是 keep:
       commit reader recurrent + conv 状态

3. final model norm + LM head

4. full_attention memory commit（由状态机统一执行）
   compress: 只追加 Beacon K/V；keep: 追加全部 K/V

5. loss 累积（只对非 -100 位置，即生成片段）

linear writer 每个 linear layer 内立即提交该层状态；full-attention K/V 在整个模型窗口前向完成后由状态机统一选择并追加。

8. 压缩边界后的严格不变量

对任意已完成压缩的 <information> 窗口，持久 memory 必须满足：

M_persistent = {
    full_attention: Beacon K/V only,
    linear_attention: writer recurrent state only,
    convolution: 无该压缩窗口的任何状态
}
不存在：文档 full-attention K/V · 文档窗口原生 GatedDeltaNet final state · 窗口尾部因果卷积 state · HuggingFace DynamicCache 隐藏旁路。

因此压缩窗口到后续生成的计算图只能经过 Beacon 载体：

9. 梯度如何到达 Writer

文档与 Beacon 位置均为 -100，没有直接 LM loss。梯度经后续 answer loss 传播：

answer loss
  -> 后段 linear-attention 输出
  -> 持久 writer recurrent state
  -> BeaconLinearStateWriter
  -> Beacon hidden states
  -> 文档 reader 激活

所以 Beacon 表示学习的是“对后续 reasoning/search/answer 有用的信息”，而非重建全部文档。测试 test_linear_writer_receives_gradient_from_post_compression_tokens 验证了压缩后 token 的 loss 能到达 linear writer。LoRA 训练时 beacon* 参数被重新设 requires_grad=True，全量训练。

10. 配置真实语义（Reader/Writer 相关）

参数作用
beacon_window文档 / keep 段单次处理窗口长度
beacon_ratio每约 r 个原始文档 token 生成 1 个 Beacon
beacon_paramBeacon 独立使用哪些 full-attention 投影（默认 q k v）
beacon_posappend（窗口尾追加）或 intersect（chunk 内每 ratio 插入）
beacon_linear_writer_ranklinear state writer 低秩瓶颈，控制参数量与表达力（默认 128）
beacon_embed_initBeacon embedding 从 EOS / BOS 初始化
一句话总结：Reader 在压缩窗口内临时读完检索文档后即弃；Writer 只从 Beacon 激活经低秩网络重建固定尺寸的持久循环状态。配合 full-attention 层只提交 Beacon K/V，后续 reasoning、继续搜索与回答统一使用 Beacon 压缩记忆，彻底杜绝原始文档在 Qwen3.5 线性注意力状态中的旁路。
